# Dataset: From Order to Payment (fictional)

All data is **invented** and generated by `generate_dataset.py` (seed 2025). Same seed means the same files every time.
Company, supplier names and amounts are fictional. Any resemblance to real companies is unintended.

## Files
| File | Rows | Content |
|---|---|---|
| `suppliers.csv` | 25 | Supplier, category, perishable flag, payment terms |
| `invoices_scenarios.csv` | 2 × 1,121 | Each 2025 invoice, once per scenario (`as_is`, `to_be`) |
| `kpi_summary.json` | — | KPIs per scenario, exception mix, all scenario assumptions |

## How the before/after works
The **same invoices with the same exceptions** go through two simulated processes. Only the process rules change, and they are listed under `assumptions` in `kpi_summary.json`. The results are *simulated on sample data*, not measured in a real company.

## Main assumptions
- AS-IS: about 30% of clean invoices match automatically on the day they arrive; the rest wait for a manual check. About 40% of approvers answer within 1–3 working days, the rest take 4–14 (two more above the approval threshold).
- TO-BE: automatic same-day match for clean invoices, an exception queue with an owner, a 3-working-day approval SLA with reminders (85% on time), and a supplier + invoice-number duplicate check that catches 90% of duplicates (re-numbered ones can still slip through).
- Full list: `assumptions` in `kpi_summary.json`.
- Duplicates use their own random stream (seed + 1), so both scenarios see the same duplicates.

## Headline results (AS-IS → TO-BE)
| KPI | AS-IS | TO-BE |
|---|---|---|
| Median approval time | 15 days | 3 days |
| Paid on time | 94.1% | 99.8% |
| Fresh meat paid ≤ 30 days | 82.3% | 99.4% |
| Approved within 5 days | 7.5% | 69.6% |
| First-time match | 19.8% | 70.5% |
| Duplicate invoices paid | 23 (€214,429) | 4 (€17,162) |

## Data dictionary: invoices_scenarios.csv
| Field | Meaning |
|---|---|
| scenario | `as_is` (manual process) or `to_be` (redesigned process) |
| invoice_id, supplier_id, supplier_name, category | Invoice and supplier identifiers |
| perishable | True for fresh meat (30-day legal payment limit, D.Lgs. 198/2021) |
| channel | `XML (SDI)` e-invoice or `PDF` (PDF-only invoices: InvoiceFlow intake check in TO-BE) |
| amount_eur | Invoice total |
| exception | `none`, `quantity_difference`, `price_mismatch`, `missing_po`, `duplicate` |
| invoice_date, received_date, due_date | Issue date, date received by accounts payable, due date from payment terms |
| matched_date | Date invoice, order and goods receipt were reconciled |
| approved_date, paid_date | Empty when a duplicate was blocked |
| auto_matched | True when matched with no manual step: about 30% of clean invoices in the AS-IS (same-day ERP match), most clean invoices in the TO-BE |
| outcome | `paid`, `duplicate_blocked`, `duplicate_paid` |
| cycle_days | approved_date − received_date (calendar days) |
| days_to_pay | paid_date − invoice_date |
| paid_on_time | paid_date ≤ due_date |
